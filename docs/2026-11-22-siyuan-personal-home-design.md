## 1. 背景与核心意图（Intent & Why）

思源笔记原生缺少一个开箱即用的“个人主页”，导致每次打开思源都要在左侧文档树里逐层翻找最近读过或修改过的笔记。同时，当前工作区为了实现习惯打卡、轻量待办和日记日历，同时挂载了 `任务笔记管理`（v7.3.0）和 `日历面板`（`arco-calendar` v2.4.0）两个外部插件：前者功能极度庞大、带有浓重的截止时间节点与严肃任务压迫感，而日常实际只需要粗粒度任务和习惯打卡；后者虽然轻量，但又额外占用侧边栏/入口位置。

因此，本项目的核心意图是**从零打造一个完全自主可控、轻盈克制的统一「个人主页」插件**，将“笔记总览与最近读写”、“今日日记与日记月历”、“习惯打卡”和“轻量无时间节点任务”收拢到一个专属标签页内，达成以下效果：

1. 卸掉 `任务笔记管理` 和 `日历面板`，减少插件碎片化与侧边栏图标堆积；
2. 打开思源即可一眼掌握笔记动态与今日节奏，顺手完成打卡与待办整理，需要深度阅读或写作时点卡片直达原文档；
3. 底层数据与界面高度自主、代码结构清晰，后续可按个人使用习惯低成本持续迭代。

## 2. 目标、非目标与反目标

### 2.1 目标（Goals）

- **读写分层清晰**：文档性质的内容（最近改过/读过笔记、今日日记）定位为美观的总览预览卡片 + 一键跳转入口；行动性质的内容（习惯打卡、轻量任务）直接在主页上完成增删改查和勾选。
- **现代文档预览体验**：参考 Obsidian `Notebook Navigator` 的设计思想，文档卡片呈现标题、图标、正文摘要、自动提取的题头图/首图缩略图、笔记本路径、标签与相对时间。
- **无时间压迫感的轻量任务**：彻底放弃截止日期和闹钟提醒，仅围绕“轻重缓急（优先级）”与“不同维度（自定义分组）”管理近期待办。
- **双维度习惯打卡统计**：参考 `任务笔记管理` 的习惯模块优点，同时支持“坚持天数/跨度/周次”与“可选投入耗时（分钟）”两个统计维度，支持历史补卡与回顾。
- **完整承接日历精华**：吸收 `arco-calendar` 的日记月历与年度写作热力图能力，直接融入主页，卸载原插件后不损失核心体验。
- **极简入口**：零侧边栏 Dock 图标，仅保留顶栏单一入口 + 快捷键 + 可选启动自动打开。
- **平滑可演进**：数据/服务层与视图层解耦，当前采用单页工作台（方案一），未来如某模块变重，可零数据迁移演进为带顶栏子页切换的微型应用（方案三）。

### 2.2 非目标（Non-Goals）

- **不迁移历史数据**：不读取也不导入原 `任务笔记管理` 的已有任务与打卡记录，轻装全新开始。
- **不做重型时间管理**：不做截止时间（DDL）、定时推送提醒、Webhook 通知、番茄钟倒计时、多级项目甘特图、外部 ICS 日历订阅或农历节假日日历。
- **不在主页内嵌文档编辑器**：不在主页直接内嵌完整 Protyle 编辑器来编辑日记或笔记正文，保持主页轻快，点击卡片跳去思源原生标签页编辑。
- **不把任务/打卡回写为思源 Markdown 块**：不污染用户的笔记树和全局全文搜索索引。
- **不提供侧边栏 Dock 面板**：不在左侧或右侧 Dock 栏新增常驻图标。

### 2.3 反目标（Anti-Goals）

即使功能技术上全部跑通，出现以下任一情况都视为设计失败：

- **拖慢思源启动或切换卡顿**：启动时做重查询或每次切换标签全量扫描导致明显掉帧。
- **界面像 ERP 表单或重型看板**：视觉拥挤、弹窗泛滥、打卡或记一条小任务需要点三四下。
- **主题割裂**：硬编码亮/暗配色，导致切换思源明暗模式或更换第三方主题后界面违和。
- **数据静默丢失**：插件更新、误操作或跨端同步时覆盖丢失用户的任务和打卡历史。

## 3. 架构方案对比与决策（Approaches）

在进入详细设计前，我们对比了三条实质不同的实现路线：

| 方案 | 核心做法 | 主要优势 | 主要代价与取舍 |
|------|----------|----------|----------------|
| **方案一（已选）**：单页卡片工作台 + 插件私有结构化存储 | 一屏 Bento 卡片工作台；笔记/日记/热力图实时查思源原生 SQL/API；最近读过、轻量任务、习惯打卡存在思源自动同步的插件专属目录 `data/storage/petal/` | 响应最丝滑、数据结构极干净、零污染笔记库、维护迭代成本最低，且未来可平滑演进为方案三 | 小任务与打卡记录本身不是 Markdown 块，无法在思源全局搜索中直接搜到（通过导出备份 + 任务可选挂接笔记链接缓解） |
| **方案二**：单页卡片工作台 + 思源文档块作为任务/习惯数据源 | 将任务与打卡直接存为指定思源文档内的 Markdown 列表/块属性，主页负责双向解析与回写 | 任务与打卡天然成为普通笔记，可全局搜索、反链与手工编辑 | 需处理 Kramdown/DOM 解析、SQL 索引延迟、手改格式冲突，且每日打卡流水会严重污染笔记库与搜索结果 |
| **方案三**：单入口多子页微型应用 | 同样是顶栏单一入口和私有存储，但打开后内部拆分为“总览 / 任务 / 习惯 / 笔记”多个子视图 | 模块极度膨胀时单页空间更宽敞 | 对当前轻量化需求多了一层切换心智，削弱“打开即总览、顺手点完就走”的直觉体验 |

**选型理由与演进约束**：用户明确选择**方案一**。为了保证未来确实能无痛从方案一演进到方案三，本设计硬性要求**数据层（Storage & SiYuan Services）、领域计算层（Domain Logic）与页面布局容器（HomePage Layout）完全解耦**——每个功能区块（统计热力图、今日日记、最近读写、日记月历、习惯打卡、轻量任务）均作为独立的无耦合模块开发，仅由顶层容器负责网格排布。

## 4. 环境与硬约束（Constraints）

1. **思源阅读历史缺失约束**：思源 SQLite 数据库（`blocks` 表）原生仅记录文档的 `created` 和 `updated`（`YYYYMMDDHHMMSS` 格式），不持久化“最近读过/浏览过”记录。因此，“最近读过”必须由插件监听思源前端 `switch-protyle` 事件自行记录并持久化，数据自插件启用后开始积累。
2. **思源原生同步机制利用**：通过思源插件 API `Plugin.saveData(storageName, content)` / `Plugin.loadData(storageName)` 读写的数据会自动存放在 `<workspace>/data/storage/petal/siyuan-personal-home/` 下，天然受思源自带数据同步覆盖。
3. **样式隔离与主题自适应**：插件全部 DOM 挂载在独立命名空间根容器 `.sph-root` 下；所有色彩、背景、文字、边框、圆角优先映射到思源原生 CSS 变量（如 `--b3-theme-background`、`--b3-theme-surface`、`--b3-theme-on-background`、`--b3-theme-on-surface`、`--b3-theme-primary`、`--b3-border-color`、`--b3-list-hover`），并支持开关决定是否使用思源主题强调色。
4. **前端构建隔离**：使用 React + TypeScript + Vite 打包为独立插件产物（`index.js` + `index.css` + `plugin.json`），不依赖宿主全局框架，不污染全局样式或全局对象。

## 5. 入口与整体信息架构（UX & Layout）

### 5.1 入口与标签页行为

- **顶栏图标**：在思源顶栏（TopBar）注册唯一入口图标（支持设置左侧或右侧，默认左侧靠近工作流区域），悬停提示「个人主页」。
- **快捷键**：注册插件命令「打开个人主页」（默认快捷键如 `Alt+Shift+H`，可在思源设置 -> 快捷键中自定义）。
- **单实例防重复打开**：通过 `addTab` 注册自定义标签页类型（`sph-home-tab`）。点击顶栏图标或触发快捷键时，若当前窗口已存在个人主页标签页，直接激活切换过去，不重复打开多个主页。
- **启动自动打开**：提供插件设置项「启动思源时自动打开个人主页」（默认开启），在 `onLayoutReady` 阶段延迟打开主页标签页（若上次会话恢复中已存在该标签页则复用而不重复创建）。
- **零侧边栏 Dock**：不调用 `addDock`，保持侧边栏干净。

## 6. 五大核心模块详细设计

### 6.1 模块一：笔记统计与年度写作热力图

**核心指标（顶栏 4 张紧凑统计卡）**：
- **文档总数**（全工作区已打开笔记本）：`SELECT COUNT(*) AS cnt FROM blocks WHERE type = 'd'`
- **总字数 / 总块数**（全工作区已打开笔记本）：默认展示总字数（汇总叶子内容块 `SUM(length)`，剔除容器块重复计数：`WHERE type IN ('p','h','c','m','t','html','callout')`），悬停或副标题显示总块数。
- **近 7 天活跃**（全工作区已打开笔记本）：近 7 天内 `updated >= YYYYMMDD000000` 的文档数量（`type = 'd'`）。
- **今年日记天数**（当前选定的 `activeDiaryNotebookId`）：当年在该日记本中存在 `custom-dailynote-YYYY%` 属性的去重日期天数。

**年度写作热力图**（参考 `arco-calendar` 精华）：
- 聚合范围为**全工作区所有打开的笔记本**，支持年份切换（`< 2026 >`），按周列排列（支持设置每周起始日为周一或周日）。
- **活跃度归属逻辑**：
  - 属于日记文档（带 `custom-dailynote-YYYYMMDD` 属性）的内容块，按该日记对应的 `YYYYMMDD` 归档；
  - 普通文档的内容块，按块 `created` 的日期 `YYYYMMDD` 归档；
  - 仅统计有效内容块（排除文档根块 `d` 本身及纯容器壳），按每日块数映射为 0~4 五级色阶（跟随主题色或中性色）。
- **交互**：鼠标悬停显示「日期 · 新增/记录 N 个内容块 · 当日日记状态」；点击任意日期格子时，统一针对当前共享的 `activeDiaryNotebookId` 打开或创建该日日记（避免误建到其他笔记本）；底部显示当年合计活跃块数与活跃天数。

### 6.2 模块二：日记月历与今日日记预览卡片

**统一的日记本状态（`activeDiaryNotebookId`）**：
- 顶层共享状态 `activeDiaryNotebookId` 同时驱动「迷你日记月历」、「今日日记大预览卡片」、「今年日记天数」统计以及「点击年度热力图打开/创建日记」，确保全页面对“当前日记本”的认知完全一致，同时各组件仅通过 props/订阅接收该 ID，不破坏模块解耦。
- **启动解析优先级**：优先读取思源原生配置 `local-dailynoteid`（与思源原生 `Alt+5` 写日记保持一致）；若未配置或对应笔记本已关闭，回退到插件 `settings.json` 中记住的 `diaryNotebookId`；若仍无效，则回退到思源当前第一个未关闭的笔记本。
- **切换同步**：在月历头部下拉切换日记本时，同时更新共享状态 `activeDiaryNotebookId`、写入插件 `settings.json`，并同步更新思源的 `local-dailynoteid`。

**迷你日记月历**：
- 显示当前月份日期网格，支持切换上月/下月、年月选择、以及一键回到「今天」。
- **视觉标记**：
  - 已有日记的日期：主题色淡圆底标记；
  - 当日（今天）：日期下方圆点高亮（选中态自动反色）；
  - 日记内存在未完成任务列表项（`type = 'i' AND subtype = 't' AND markdown LIKE '%[ ]%'`）的日期：右上角显示一枚柔和的琥珀色小圆点（可在设置中关闭）。
- **点击行为**：
  - 若该日已存在对应日记本的日记（查询 `attributes` 表中 `name = 'custom-dailynote-YYYYMMDD' AND box = notebookId`），直接调用 `openTab` 打开；
  - 若该日是**今天**且无日记，直接调用思源官方接口 `/api/filetree/createDailyNote` 创建并打开（完全遵循思源原生路径模板与日记模板）；
  - 若该日是**过去或未来某天**且无日记，通过 `/api/notebook/getNotebookConf` 获取该笔记本的 `dailyNoteSavePath` 与 `dailyNoteTemplatePath`，用 `/api/template/renderSprig` 渲染目标日期的路径，调用 `/api/filetree/createDocWithMd` 创建文档并写入属性 `custom-dailynote-YYYYMMDD`（若配置了模板，调用 `/api/template/render` 渲染后插入正文），最后打开该文档。

**今日日记大预览卡片**：
- 固定置于左栏最上方，展示今日日期、星期。
- **今日已有日记时**：渲染为大号预览卡片——显示日记标题、前 3~4 行纯文本正文摘要、自动提取题头图或首张正文图片缩略图、当前字数与最后更新时间；点击整卡直达日记编辑页。
- **今日尚无日记时**：展示清爽的引导空状态（如「今天还没有开始记录」），附带醒目主按钮「写今天的日记」，点击即创建并跳转。

### 6.3 模块三：最近改过与最近读过（Notebook Navigator 风格预览卡片）

**视图切换与过滤**：
- 顶部提供「最近改过」/「最近读过」两个主 Tab（默认显示「最近改过」，记住上次选择）。
- 提供轻量过滤控件：开关「隐藏日记」（避免日记占满最近列表，默认关闭或由用户一键切换）、按笔记本筛选、以及客户端即时标题关键词过滤。
- 默认首屏展示 12 条，底部提供「加载更多」按需翻页。

**双数据源机制**：
1. **最近改过**：直接查思源 SQL：
   ```sql
   SELECT id, box, hpath, content, tag, ial, created, updated
   FROM blocks
   WHERE type = 'd'
   ORDER BY updated DESC
   LIMIT ? OFFSET ?
   ```
   （当开启「隐藏日记」时，过滤掉 `attributes` 中存在 `custom-dailynote-%` 的 `root_id`）。
2. **最近读过**：
   - 插件在生命周期中监听思源事件总线 `eventBus.on('switch-protyle', ...)`（以及文档加载完成事件），获取当前激活文档的 `rootID`。
   - **防抖去噪**：仅当用户在某文档停留超过 `1500ms`（避免快速划过多个标签页产生垃圾记录），才更新 `recent-reads.json` 中该文档的 `lastReadAt` 与 `readCount`，采用 LRU 策略最多保留 100 条。
   - **渲染校验**：展示「最近读过」列表时，将这批 `docId` 批量查询思源 SQL 补全最新标题、路径、摘要与缩略图；对于已在思源中被删除的文档，自动剔除并异步清理缓存。
   - **冷启动提示**：首次安装还没有阅读记录时，展示温和说明：「从现在开始，你打开浏览过的笔记会自动出现在这里」。

**预览卡片元数据提取（Notebook Navigator 风格）**：
每张卡片采用清晰的横向图文结构（左侧文字区 + 右侧可选方形圆角缩略图，无图时文字自动占满宽度，不留丑陋占位框）：
- **图标与标题**：解析文档 `ial` 中的 `icon`（Emoji 十六进制码或自定义图标路径）+ 文档标题（`content`）。
- **正文摘要（2~3 行截断）**：批量查询该文档前若干非空文本子块（`type IN ('p','h','l','b','callout')`），按文档顺序拼接并清洗 Markdown 符号与冗余空白，截取前约 160 字。
- **自动缩略图**：
  1. 优先解析文档 `ial` 中的 `title-img`（题头图，剔除纯色渐变背景，保留真实图片 URL/本地 `assets/` 路径）；
  2. 若无题头图，查询 `assets` 表中属于该 `root_id` 的首张图片文件（`.png/.jpg/.jpeg/.webp/.gif/.avif`）；
  3. 找不到图片则优雅隐藏缩略图区域。
- **底部元信息**：所在笔记本名称、最多 3 个标签 chip（来自文档 `tag` 字段）、以及人性化相对时间（如「刚刚」「12 分钟前」「昨天 21:30」，在「最近读过」Tab 下显示阅读时间，在「最近改过」Tab 下显示修改时间）。
- **点击行为**：整张卡片可点击，调用思源 `openTab({ app, doc: { id: docId } })` 直接跳转；支持右键或悬浮快捷图标在新标签页打开。

### 6.4 模块四：习惯打卡（双维度统计 + 轻快交互）

**核心数据结构（`habits.json`）**：

```ts
export interface HabitItem {
  id: string;
  name: string;
  icon: string;                   // Emoji，默认如 ✨
  color: string;                  // 柔和强调色标识
  frequencyType: 'daily' | 'weekly';
  weeklyTarget: number;           // daily 固定为 7；weekly 为 1~6（如每周 3 次）
  trackDuration: boolean;         // 是否开启“投入耗时（分钟）”记录
  defaultDurationMinutes?: number;// 开启耗时时的默认分钟数，支持一键打卡不弹窗
  linkedDocId?: string;           // 可选：关联一篇思源复盘/记录文档
  createdAt: string;              // YYYY-MM-DD（用于计算“已坚持跨度”）
  archived: boolean;
  deleted?: boolean;              // 软删除标记，用于跨端同步合并防复活
  sortOrder: number;              // 通过编辑/管理弹窗的“上移/下移”调整，v1 不做拖拽
  updatedAt: number;              // 记录级最后修改时间戳，用于跨端同步合并
}

export interface HabitCheckin {
  done: boolean;
  durationMinutes?: number;       // 本次投入分钟数（仅开启耗时时使用）
  note?: string;                  // 可选极简一句话备注（在详情抽屉中可填）
  checkedAt: number;              // 打卡时间戳
  updatedAt: number;              // 记录级最后修改时间戳，用于跨端同步合并
}

export interface HabitsStore {
  version: 1;
  habits: HabitItem[];
  // key 为 habitId -> YYYY-MM-DD -> Checkin
  checkins: Record<string, Record<string, HabitCheckin>>;
}
```

**双维度“坚持时长”计算规则（纯函数 `habitStats.ts`，严格可测）**：
1. **天数与跨度维度（所有习惯默认展示）**：
   - **主连击指标（按频率区分口径，避免歧义）**：
     - `daily` 习惯：按**连续打卡天数**计算（`currentStreakDays` / `bestStreakDays`）。当前连击从今天起算（若今天尚未打卡则从昨天起算，避免早上刚打开就显示归零），主页显示 `连续 X 天`；
     - `weekly` 习惯（`weeklyTarget` 为 1~6）：按**连续达标自然周数**计算（`currentStreakWeeks` / `bestStreakWeeks`，对齐用户设置的 `weekStartDay`；若本周已达标则计入本周，否则从上周起往前连续计周），主页显示 `连续 X 周`。
   - **本周完成次数（`thisWeekCount`）**：按设置的周起始日（周一或周日）计算当前自然周内 `done === true` 的天数，显示为 `本周 Y/7 次` 或 `本周 Y/Z 次`。
   - **累计坚持天数（`totalDays`）**：历史上所有 `done === true` 的总天数。
   - **已坚持跨度（`spanDays`）**：从首次打卡日（若尚未打卡则从 `createdAt`）到今天经过的自然日跨度（如「已坚持 45 天」）。
2. **投入耗时维度（开启 `trackDuration` 的习惯额外展示）**：
   - **今日耗时**：今天记录的分钟数；
   - **本周累计耗时**：当前自然周所有打卡的 `durationMinutes` 之和；
   - **历史总投入时长**：全部打卡的 `durationMinutes` 之和，自动格式化（如 `18h 30m` 或 `45m`）。

**主页与详情交互**：
- **主页习惯行**：保持极度轻快——左侧一个圆形一键勾选框，点一下立即完成今日打卡（若开启了 `trackDuration`，默认填入 `defaultDurationMinutes` 如 30 分钟，同时右侧会出现一个小小的 `30m` 胶囊，点击即可原地微调本次分钟数，无需每次弹窗打断）；中间是习惯名 + **当前自然周 7 天圆点状态条**（按 `weekStartDay` 对齐本周 7 天：已打卡为实心主题色圆点、已过未打为空心圆点、今天加细外环标识、本周未来日期为浅灰小点占位，确保与右侧 `本周 Y/Z 次` 视觉完全一致）；右侧精简显示 `连续 X 天`（每日）或 `连续 X 周`（每周）+ `本周 Y/Z`（开启耗时则附 `· 本周 Xh`）。
- **习惯详情抽屉/弹窗**：点击习惯标题打开，展示：
  - 4 个核心统计数字卡（当前/最长连击、累计天数/已坚持跨度、本周完成率、累计投入时长）；
  - 可翻月的月度打卡日历格子（支持点击任意历史日期补卡、取消打卡或修改当天耗时与一句话备注）；
  - 编辑习惯属性、上下调整排序、关联/跳转思源笔记、归档（归档后保留全部历史统计但移出每日列表）与删除操作。

### 6.5 模块五：轻量任务管理（零时间节点，轻重缓急 × 自定义维度）

**核心数据结构（`tasks.json`）**：

```ts
export type TaskPriority = 'high' | 'medium' | 'low';

export interface TaskItem {
  id: string;
  title: string;
  priority: TaskPriority;         // 轻重缓急：高 / 中 / 低
  categoryId: string;             // 所属维度 ID
  completed: boolean;
  completedAt?: number;
  createdAt: number;
  updatedAt: number;              // 记录级最后修改时间戳，用于跨端同步合并
  deleted?: boolean;              // 软删除标记，用于跨端同步合并防复活
  sortOrder: number;              // 同优先级内顺序保留，v1 不引入拖拽排序
  linkedDocId?: string;           // 可选：关联思源文档 ID
  linkedDocTitle?: string;        // 冗余缓存标题，悬停或展示用
}

export interface TaskCategory {
  id: string;
  name: string;                   // 如：工作、学习、生活、随手记
  color: string;
  sortOrder: number;              // 通过维度管理弹窗的“上移/下移”调整
  updatedAt: number;
  deleted?: boolean;
}

export interface TasksStore {
  version: 1;
  categories: TaskCategory[];
  tasks: TaskItem[];
}
```

**主页交互**：
- **极速录入**：卡片顶部一行输入框，输入标题回车即创建；输入框末尾带两个极简胶囊按钮，顺手点选优先级（红/琥珀/灰）和维度分组（默认继承当前筛选维度，避免重复选）。
- **双视图组织**：
  - **按轻重缓急视图**：自动按 高 → 中 → 低 分段排序（同级内按 `createdAt` 降序），一眼先看最重要的事；
  - **按维度分组视图**：按「工作 / 学习 / 生活 / 自定义维度」分组展示，每组内按优先级（高 → 中 → 低）排序。
  - 顶部维度筛选条支持一键只看某个维度或「全部」，并提供「管理维度」小入口（自由增删改名及上/下调整展示顺序）。
- **轻量操作（v1 不引入拖拽排序）**：
  - 点击复选框一键完成，自动平滑移入底部可折叠的「已完成 (N)」区域（支持取消勾选恢复、单条删除、以及「清空已完成」）；
  - 点击任务优先级小圆点可循环切换 高/中/低，点击维度标签可快速改组，双击标题原地修改；
  - 悬停操作区提供「关联思源笔记」按钮（调用思源文档搜索接口快速选中一篇笔记挂载），挂载后任务右侧显示一个小文档图标，点击即跳去对应笔记。

## 7. 数据存储、同步与灾备策略

| 文件名（位于 `data/storage/petal/siyuan-personal-home/`） | 存储内容 | 更新频率与大小控制 |
|---|---|---|
| `settings.json` | 入口位置、启动自动打开、周起始日、热力图折叠态、日记本 ID、是否使用主题强调色、隐藏日记开关等 | 低频，约 1~2 KB |
| `tasks.json` | 自定义维度列表与轻量任务列表（含 `version: 1`） | 中频，几十 KB 以内 |
| `habits.json` | 习惯定义与每日打卡记录（含 `version: 1`） | 每日几次，几年仅数十 KB |
| `recent-reads.json` | 最近阅读文档列表（LRU 上限 100 条） | 切文档防抖后写入，约 10 KB |

**一致性、同步保护与安全保障**：
1. **结构化版本迁移**：所有 JSON 文件根部均带 `version` 字段，未来升级字段时由 `storageService` 自动做无损向前兼容填充。
2. **跨端同步热重载与记录级合并（满足 Anti-Goal #4）**：
   - 插件监听思源 `sync-end` 事件，云同步完成后自动重新读取磁盘上的 `tasks.json` / `habits.json` / `settings.json` 并刷新主页状态，防止长驻主页标签页停留在过期内存快照上；
   - 每次写入 `tasks.json` 或 `habits.json` 前，串行写队列先从磁盘执行一次 read-before-write：若磁盘文件与上次加载基线不同，自动按**记录级 `updatedAt`（LWW per record）+ `deleted` 软删除标记**逐条合并（不同任务、不同习惯或不同日期的打卡记录互不覆盖）后再写回；
   - 同一份数据在覆盖写入前，如检测到结构异常直接拒绝写入并保留原文件；超过 30 天的软删除记录可在合并时按需垃圾回收（GC）。
3. **JSON 一键备份与恢复**：在插件设置弹窗中提供「导出全部个人数据（JSON）」与「导入覆盖恢复（JSON，导入前做 schema 校验与二次确认）」，确保数据 100% 掌握在用户自己手里。
4. **物理拆分降低冲突面**：将高频变动的 `recent-reads.json` 与核心业务数据 `tasks.json`/`habits.json` 物理拆分存储于 `data/storage/petal/siyuan-personal-home/`，利用思源官方同步的同时将文件级冲突概率降到最低。

## 9. 决策归属说明

### 9.1 已与用户对齐拍板的事项
- 采用**方案一**：单页卡片工作台 + 插件私有结构化存储，数据与视图解耦以支持未来演进方案三；
- 独立自研，不迁移 `任务笔记管理` 历史数据，最终替代 `任务笔记管理` 与 `日历面板`；
- 读写分层：文档/日记做 `Notebook Navigator` 风格预览卡片跳转，任务与习惯在主页直接操作；
- 任务彻底去掉时间节点与提醒，仅按轻重缓急与自定义维度组织；
- 习惯打卡同时保留“连续天数/周次/已坚持跨度”与“可选投入耗时（分钟）”两个维度；
- 零侧边栏 Dock 图标，统一在主页标签页内使用；
- 插件标识 `siyuan-personal-home`，源码放在当前工作区下同名目录。

### 9.2 设计师作出的默认决策（供审阅时核对调整）
- 启动自动打开主页默认设为开启（可在设置中关闭）；
- 最近读过设置 `1.5s` 停留防抖与 `100` 条 LRU 上限；
- 日记本统一以思源原生 `local-dailynoteid` 为准，在月历切换时双向同步并联动今日日记、今年日记天数和点击热力图打开/创建行为；其余笔记统计与热力图则面向全工作区打开的笔记本；
- 习惯连击口径按频率区分：`daily` 习惯计连续打卡天数，`weekly` 习惯计连续达标周数；主页的 7 点状态条统一表示当前自然周（按周起始日对齐），确保与“本周 X/Y 次”严格一致；
- 任务默认内置 4 个初始维度（工作、学习、生活、随手记），用户可自由增删改名；v1 不引入拖拽排序，习惯与维度通过管理弹窗的「上移/下移」调整顺序；
- 数据层采用 `sync-end` 监听 + 写入前按记录级 `updatedAt` 合并与软删除防复活，避免跨端同步或长驻标签页误覆盖历史数据；
- 技术栈选用 React 19 + TypeScript + Vite + Tailwind CSS 4 + Lucide + Vitest。

### 9.3 留给实现阶段自由决定的细节
- 具体视觉间距、字号梯度、动画过渡时长与卡片阴影细腻度；
- SQL 批量查询的具体拆批大小与前端内存短缓存策略；
- 键盘快捷键辅助交互（如弹窗 Esc 关闭、输入框聚焦快捷键等）；
- 英文国际化文案细节与空状态插画/文案润色。
